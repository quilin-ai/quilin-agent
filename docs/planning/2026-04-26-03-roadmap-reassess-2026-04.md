## 3. Multi-agent + Self-evolution 决议（Codex reconcile 2026-04-26 已 ack）

### 3.1 Multi-agent — 保留 hand-rolled，Claude Agent SDK 仅 Iter F Day 0 adapter spike

**Codex independent view**: 保留 Quilin hand-rolled supervisor/mesh contract 为主线；Claude Agent SDK 只作为 Iter F spike 的 Anthropic adapter 候选，不能现在替换 hand-rolled mesh。

**风险评估（实证后定稿）**：

- **BLOCKING**：Claude Agent SDK 是 Claude Code harness as library，强绑定 Anthropic / Bedrock / Vertex 路线 → 冲突 Quilin 的 Vercel AI SDK **model-agnostic 全面碾压** 核心定位
- **HIGH**：TS V2 preview；subagent / agent teams 语义和 Quilin "main agent 永不阻塞 + progress protocol + WriteAuthority" 不等价，必须实测
- **HIGH**：Agent SDK 自带 tool loop / permissions / sessions，直接替换会绕过或重复 Quilin 已落地的 loop / OTel / WriteAuthority / scratchpad

**采纳点**：
- subagent + MCP + hooks 值得借鉴 — 在 Iter F Day 0 做 adapter spike
- 不是"换框架"，而是"Iter F Day 0 评估 Claude Agent SDK 作为 Anthropic-flavor adapter 的可行性"
- 评估通过 → 主线 hand-rolled mesh + Claude Agent SDK adapter 双轨；评估失败 → 仅主线 hand-rolled

**Iter F 06/11 状态**：保留 hand-rolled supervisor contract + mesh-sdk transport；评估 Claude Agent SDK adapter，不在本 reassessment 直接替换 runtime

### 3.2 Self-evolution — 部分采纳 DSPy+GEPA 作为 optimizer engine

**Codex independent view**: 采用 DSPy 3.1 + GEPA 作为 optimizer engine 候选，但不替换 Quilin 的 trajectory schema / skill creation / User Insight / WriteAuthority gate。

**风险评估（实证后定稿）**：

- **采纳**：GEPA 官方定位是 reflective prompt optimizer，可吃 trace + metric + textual feedback；与 trajectory-driven prompt/skill optimization 对齐
- **HIGH**：DSPy/GEPA 是 Python-only — 但放在 `providers/` 作为 MCP/CLI evolution worker 可接受（与 OmniMem 同位）
- **HIGH**：GEPA 输出只能是 **proposal artifact**，必须走 `propose-not-apply` + WriteAuthority / human review；优化产物绝不直接 apply
- **MEDIUM**：需 Iter F Day 0 spike 冻结 optimizer 输入/输出契约（trajectory sample / metric / budget / candidate diff format）

**Iter F 10 状态**：部分采纳 — DSPy+GEPA wrapper for prompt/tool/skill optimization；Skill loader / User Insight / WriteAuthority / idle budget 保留 hand-rolled

### 3.3 综合决议

- **不全替换 framework**：Quilin 主线代码量级会改变，但 model-agnostic + WriteAuthority + 4-tier safety + Skills 全保留
- **adapter / wrapper 模式为主**：Claude Agent SDK 作 Iter F Anthropic adapter 候选；DSPy GEPA 作 evolution optimizer engine 包装
- **Iter F Day 0 spike 必须**：在 Iter F runtime 实现前先做 spike 冻结契约，避免 hand-rolled vs adapter / wrapper 接口不一致返工
