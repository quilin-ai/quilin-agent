## Findings By Severity

### BLOCKING

#### B1. GAIA tasks cannot pass the current runner because collect still emits only `patch`

Evidence:

- `benchmarks/src/runner/runner.ts:324` returns `{ patch: loopOutput }` for every dataset.
- `benchmarks/src/runner/runner.ts:353` still prompts the agent to "Produce only the final patch diff."
- `benchmarks/src/scorers/gaia-exact-match.ts:50` only accepts `model_answer` or `answer`.
- `benchmarks/src/submissions/gaia-jsonl.ts:16` requires `model_answer` or `answer`.
- `docs/planning/2026-04-26-02-iter-e3-gaia-bfcl.md:112` requires GAIA loader + scorer + submission end-to-end in DockerSandbox.

Impact:

Any GAIA task run through `runBenchmarkTask` produces `output.patch`, then `gaiaExactMatchScorer` reports `missing_model_answer`. The loader/scorer/submission units can pass independently, but the required E3a path from setup -> score -> submission cannot work.

Recommendation:

Make collection dataset-aware before claiming E3a readiness. For GAIA, require the agent loop to return strict JSON containing `model_answer` and optional `reasoning_trace`, parse it in `collect`, and add a runner E2E test with a `gaia` task plus `gaiaExactMatchScorer` and `gaiaJsonlAdapter`.

Confidence: high.

#### B2. GAIA scorer normalization does not match official `question_scorer`

Evidence:

- Local scorer normalizes by lowercase, trim, whitespace collapse, and edge-punctuation trimming only: `benchmarks/src/scorers/gaia-exact-match.ts:40`.
- Official scorer has type-dependent behavior: numeric answers strip `$`, `%`, and commas before float comparison; list answers split on comma/semicolon and compare element-wise; string answers remove all whitespace and punctuation before lowercase comparison. Source: GAIA `scorer.py`, lines around `question_scorer` and `normalize_str`.
- Local tests assert `"!!! Alpha, beta.???" -> "alpha, beta"` at `benchmarks/src/scorers/gaia-exact-match.test.ts:18`, which keeps internal punctuation and would disagree with official string normalization.

Impact:

Local GAIA scores can diverge from leaderboard scores. Examples: `$1,234` vs `1234`, `sea gull` vs `seagull`, and comma-separated list answers are handled differently. That creates false failures and false passes in the harness, invalidating local regression numbers.

Recommendation:

Port the official scorer semantics directly, including number normalization, comma/semicolon list handling, and full whitespace/punctuation removal for string answers. Add parity tests for numeric, list, and string cases copied from the official behavior.

Confidence: high.

### HIGH

#### H1. Attachment integrity is not covered by the cache manifest

Evidence:

- `DatasetManifest` only records one `sha256` for `data.jsonl`: `benchmarks/scripts/fetch-benchmark.ts:48`.
- `fetchBenchmark` computes that hash from `jsonl` only and writes the manifest after attachment fetch: `benchmarks/scripts/fetch-benchmark.ts:119`.
- Cache reuse checks `data.jsonl` hash and only verifies attachment existence with `access()`: `benchmarks/scripts/fetch-benchmark.ts:357` and `benchmarks/scripts/fetch-benchmark.ts:361`.
- Shared cache loader also verifies only `manifest.sha256` against the data file: `benchmarks/src/datasets/cache.ts:64`.

Impact:

If a cached GAIA attachment is modified after fetch, the manifest remains valid and both fetch cache-hit logic and `loadGaiaTasks` accept it. GAIA questions often depend on attachments, so this can silently change benchmark inputs while preserving a "valid" manifest.

Recommendation:

Add an attachment integrity strategy. Store per-attachment `file_name`, source path/URL, byte size, and sha256 in the manifest or a strict sidecar, verify it on cache hit and loader load, and refetch or fail on mismatch. Write attachments via temp files plus atomic rename so failed fetches never leave a file that looks complete.

Confidence: high.

#### H2. GAIA attachment paths are host paths, not DockerSandbox paths

Evidence:

- Loader injects `file_path: attachment.file_path` into task inputs: `benchmarks/src/datasets/gaia.ts:199`.
- `attachment.file_path` is the host absolute path under the cache dir: `benchmarks/src/datasets/gaia.ts:229` and `benchmarks/src/datasets/gaia.ts:238`.
- DockerSandbox mounts the configured cache dir into the container at `/workspace/cache`: `benchmarks/src/sandbox/docker.ts:331`.
- Runner passes raw `task.inputs` to the agent: `benchmarks/src/runner/runner.ts:359`.
- The runner path guard treats `file_path` as a path field and blocks paths outside the task workspace when used as tool args: `benchmarks/src/runner/runner.ts:139` and `benchmarks/src/runner/runner.ts:476`.

Impact:

Inside Docker, the host absolute path in `inputs.file_path` is not valid. If the agent tries to use it through a guarded tool, the guard rejects it as outside the workspace. If it tries inside the shell, the file does not exist at that host path. Attachment-bearing GAIA tasks therefore cannot reliably inspect their attachments under the hard-isolation path E3a requires.

Recommendation:

Expose a stable container-local attachment path or materialize attachments into the task workspace during setup. For example, pass `container_path: "/workspace/cache/datasets/gaia/attachments/<file>"` only when DockerSandbox cache root is known, or copy/link declared attachments into the per-task workspace and expose workspace-relative paths. Add a DockerSandbox smoke test that opens an attachment from a GAIA task.

Confidence: high.

### MEDIUM

#### M1. `file_name` validation has no length cap

Evidence:

- Attachment validation only checks `/^[A-Za-z0-9._-]+$/`, `..`, `/`, and `\`: `benchmarks/scripts/fetch-benchmark.ts:30` and `benchmarks/scripts/fetch-benchmark.ts:462`.
- Loader-side validation repeats the same shape check: `benchmarks/src/datasets/gaia.ts:219`.

Impact:

Unicode and path separators are rejected, which is good. But an unbounded ASCII name still passes validation and is then used in URLs, filesystem paths, and error strings. A malformed upstream row can force excessive memory/path work or platform-specific `ENAMETOOLONG` failures rather than a deterministic validation error.

Recommendation:

Cap `file_name` by byte length, for example `1..255` bytes, reject `.` and extensionless control names if not expected, and add tests for Unicode, path traversal, absolute paths, path separators, and length bombs.

Confidence: medium.

### LOW

#### L1. Failed attachment fetches can leave orphan partial cache state

Evidence:

- `fetchGaiaAttachmentsIfNeeded` creates the attachment directory and writes each attachment as soon as its fetch succeeds: `benchmarks/scripts/fetch-benchmark.ts:258`.
- `data.jsonl` and `manifest.json` are only written after all attachments return: `benchmarks/scripts/fetch-benchmark.ts:119`.

Impact:

The cache will not look valid because no manifest is written, so this is not the same as H1. But a failure after one successful attachment leaves orphan files in `.benchmarks/datasets/gaia/attachments`. This makes retries and debugging noisier, and it becomes riskier if future logic starts trusting pre-existing attachment files.

Recommendation:

Fetch into a temporary staging directory, verify all expected attachments, then atomically promote the staged attachment tree together with the data file and manifest.

Confidence: medium.
