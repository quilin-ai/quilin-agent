### CC-01 🔴 CRITICAL — `loop.ts` 已经是 407 LOC，2 倍于 `<200 行`契约

- **文件**：`packages/agent-core/src/loop.ts`（407 LOC）
- **契约来源**：

  - `docs/adr/adr-001-core-loop-and-language.md:282` — "保持 <200 LOC loop.ts 不变（Iter B 已稳定）"
  - `CLAUDE.md` — "Custom minimal Agent Loop (< 200 lines TS)"
  - `packages/agent-core/src/loop.ts:161` — 文件内注释 "目标: < 200 行"
- **现状**：loop.ts 已经到 407 行。其中：
  - `sanitizeReasoningParts` / `stripReasoningFromMessages` / `stripReasoningFromMessage`（~45 LOC）属于 Phase 2 临时防御
  - `saveCheckpointState` + 5 个调用点（~50 LOC）
  - `isWithinWorkspace` / `shouldTrustToolOutput`（~20 LOC）属于 injection-scanner 策略
  - tool-loop 执行体 + blocked-output counter（~60 LOC）
- **为何严重**：
  - `<200 LOC` 不是装饰性目标，它是"Claude Code 88 LOC、Codex async queue"这条竞争叙事的**可核实证据**；ADR-001 原文将其与"不引入 LangGraph"并列为核心决策

  - Iter C event-sourced 重构（D-19）的前提是 "loop 足够小可以在一次 PR 里换骨架"。407 LOC + 副作用散落已经让这条承诺不成立
- **修复路径（建议）**：
  1. 把 `sanitize*` / `stripReasoning*` 抽到 `context/reasoning-sanitizer.ts`
  2. 把 `saveCheckpointState` 抽到 `state/checkpoint-writer.ts`（接受 `phase` / `hooks` / `state`，返回 void）
  3. `shouldTrustToolOutput` 移到 `context/injection-scanner.ts`（scanner 自己决定 trust）
  4. loop 主体应剩：调 LLM → 分派 tool_calls → push 结果 → 退出判断
  5. 目标：<220 LOC（允许 10% 松动并在 ADR-001 记录，或者一次性削到 <200）
- **优先级**：Iter B 收尾前必须修掉一层（至少移出 reasoning 相关），否则 Iter C 重构会被迫先做 refactor pre-work

### PB-01 Phase 定义应该包含"行为承诺 + 安全边界 + 规格产物"

```yaml
    - source: provider reasoning_content

      mitigations: [injection-scanner, strip-on-outbound, checkpoint-sanitize]
  new_egress: []
  new_persistence:
    - location: sessions.db
      sensitive: [reasoning.signature, reasoning.encryptedContent]
      migration: schemaVersion bump
```

**优先级**：下一个 phase（B3b Phase 0）开工前。
