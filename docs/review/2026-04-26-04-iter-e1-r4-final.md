## Findings

### BLOCKING

#### BLOCKING-1. shell command option-assignment token 仍可把绝对输出路径带出 workspace

证据：

- R3 fix 后 `assertCommandContained()` 对含 `/` 或 `\` 的整个 token 调 `assertPathContained(token, workspaceDir, "command")`（`benchmarks/src/runner/runner.ts:458-463`）。
- `assertPathContained()` 只判断整个 token 是否以 `/`、`~`、Windows drive 等开头，再把非绝对字符串当作 workspace-relative 路径解析（`benchmarks/src/runner/runner.ts:472-503`）。
- 因此 `--output-document=/var/folders/.../quilin-r4-local-file` 这个 token 以 `-` 开头，不会被识别为 absolute path；代码把它当作 workspace 下名为 `--output-document=/var/...` 的相对路径，nearest-existing-path 回退到 workspace root 后放行。
- 本地 benign probe 使用 fake `shell_exec`，没有真实执行 shell、没有网络访问、没有写外部文件。关键结果：
  - `cat link-out/secret.txt`：`allowed=false`，fake tool `calls=0`，报错 `Benchmark sandbox blocked path outside workspace: command`。
  - `git clone https://x.com/y`：`allowed=true`，fake tool `calls=1`，URL 没被 R3 fix 误拦。
  - `wget --output-document=tmp/file https://x.com/y`：`allowed=true`，fake tool `calls=1`，workspace-relative assignment 可接受。
  - `wget --output-document=/var/folders/.../quilin-r4-local-file https://x.com/y`：`allowed=true`，fake tool `calls=1`。这应被拒绝。

影响：

正式 `shell_exec` 工具一旦收到这类命令，常见 CLI（`wget --output-document=...`、`curl --output ...`、其他 `--foo=/abs/path` 形式）可以把输出目标或输入路径指到 per-task workspace 外。它绕过的是 ADR-010 §3.7 的核心 workspace-only 边界，不是测试 DX 问题。

建议：

在 command-token containment 中解析 option assignment。对 `--name=value` / `name=value` 形态，若 `value` 是 filesystem path-like（`/`、`~`、`..`、Windows absolute、或相对路径含 separator），应对 `value` 本身做 containment；URL scheme（如 `https://x.com/y`）不要按 filesystem path 处理。补测试至少覆盖：

- `git clone https://x.com/y` 允许并调用 fake tool。
- `--output-document=tmp/file` 允许。
- `--output-document=/tmp/quilin-r4-local-file` 拒绝且 fake tool 不调用。
- 建议再补 `--output-document=../secret.txt` 拒绝。
